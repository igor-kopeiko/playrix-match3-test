# Match-3 Web

Match-3 игра, написанная на **C++20** с использованием **raylib** и собранная для запуска в браузере через **WebAssembly / Emscripten**.

Проект выполнен в рамках тестового задания. Помимо основной механики Match-3 реализован вариант **2.1 — «Уровни»**.

## Использование нейросети

При разработке проекта использовалась нейросеть **ChatGPT (текущая версия — GPT-5.6 Sol)** как вспомогательный инструмент.

ChatGPT имел доступ к репозиторию проекта и использовался не только для генерации отдельных фрагментов кода, но и для промежуточного анализа текущего состояния проекта. В процессе разработки ChatGPT помогал проверять структуру репозитория, сопоставлять реализацию с требованиями задания, анализировать конфигурации, документацию и результаты сборки.

После выполнения `git push` ChatGPT также использовался для повторной проверки обновлённого состояния репозитория и поиска возможных ошибок, несоответствий требованиям и потенциальных багов.

Основная игровая логика Match-3 была написана человеком. В частности, вручную реализованы и проверены механики игрового поля, поиск матчей, swaps, cascades, gravity, генерация фишек, обработка ходов, целей уровня и условий победы или поражения.

ChatGPT использовался преимущественно для разработки и проверки вспомогательных частей проекта:

- создания меню выбора уровней;
- реализации загрузки и отображения списка уровней;

- интеграции конфигураций уровней с приложением;

Сгенерированный нейросетью код проверялся, адаптировался и интегрировался в проект человеком. Архитектурные решения и основная игровая механика не были полностью сгенерированы нейросетью.

## Реализованные возможности

### Основная механика Match-3

- перестановка соседних фишек;
- поиск горизонтальных и вертикальных матчей;
- удаление совпавших фишек;
- падение фишек после удаления;
- заполнение освободившихся клеток новыми фишками;
- cascades — автоматическая обработка новых матчей, появившихся после падения;
- начальная генерация поля без готовых матчей;
- анимация перемещения, удаления и падения фишек;
- подсчёт собранных фишек для целей уровня.

### Уровни

Реализована система из **12 уровней** с постепенно возрастающей сложностью.

Для каждого уровня через JSON-конфигурацию задаются:

- размер игрового поля;
- количество доступных цветов;
- количество ходов;
- одна или несколько целей;
- начальная карта поля.

Размер поля изменяется между уровнями и достигает **16×16** на 12-м уровне.

После выполнения всех целей уровень считается завершённым. Все уровни доступны в меню выбора с самого начала, поэтому игрок может в любой момент выбрать и запустить любой уровень. Если ходы заканчиваются раньше выполнения целей, уровень считается проигранным и его можно пройти повторно.

### Карта уровня

Начальную расстановку фишек можно задавать непосредственно в JSON-конфигурации уровня.

Для клетки можно указать конкретный цвет. Если карта не задана, поле генерируется автоматически.

Это позволяет создавать уровни с заранее подготовленной стартовой конфигурацией без отдельного Level Editor.

### Загрузка уровней и Hot Reload

Уровни хранятся отдельно от кода игры в:

```text
assets/levels/
```

Конфигурации уровней можно изменять без перекомпиляции игровой логики.

Для **desktop-сборки** реализован **Hot Reload** конфигураций уровней, позволяющий изменять параметры уровня во время разработки и загружать обновлённую конфигурацию без перезапуска игры.

В **Web-сборке Hot Reload не используется** — уровни загружаются из конфигураций, включённых в Web-сборку.

## Пример конфигурации уровня

```json
{
  "id": 1,
  "name": "First Steps",
  "width": 8,
  "height": 8,
  "colors": 6,
  "moves": 15,
  "goals": [
    {
      "color": "Red",
      "amount": 10
    }
  ]
}
```

Уровень также может содержать поле `map` с начальной конфигурацией игрового поля:

```json
{
  "map": [
    ["Red", "Blue", "Green"],
    ["Yellow", "Purple", "Red"],
    ["Blue", "Green", "Yellow"]
  ]
}
```

## Управление

Игровые фишки можно переставлять выбором двух соседних клеток.

В меню выбора уровня можно запустить любой доступный уровень.

Для desktop-сборки доступна перезагрузка конфигураций уровней для проверки изменений без перезапуска приложения.

## Технологии

- **C++20**
- **CMake 3.24+**
- **raylib 6.0** — rendering, input и windowing;
- **Emscripten** — сборка C++ приложения в WebAssembly;
- **Catch2 3.15.2** — unit tests игровой логики.

Зависимости загружаются CMake через `FetchContent`, поэтому хранить их исходный код внутри репозитория не требуется.

## Структура проекта

```text
src/core/       игровая логика, не зависящая от raylib
src/app/        rendering, input и основной игровой цикл
tests/          unit tests
assets/         игровые ресурсы и конфигурации уровней
assets/levels/  JSON-конфигурации уровней
cmake/          Web shell и вспомогательные CMake-файлы
scripts/        скрипты сборки и локального запуска
```

## Сборка Windows

### Visual Studio 2022

Из Developer PowerShell:

```powershell
cmake --preset vs2022-debug
cmake --build --preset vs2022-debug
ctest --preset vs2022-debug
```

Также репозиторий можно открыть непосредственно как CMake-проект в Visual Studio 2022.

### Ninja

```powershell
cmake --preset ninja-debug
cmake --build --preset ninja-debug
ctest --preset ninja-debug
```

## Web-сборка

Для Web-сборки необходим установленный и активированный **Emscripten SDK**, а также **Ninja**.

Сборка:

```powershell
./scripts/build-web.ps1
```

Локальный запуск:

```powershell
./scripts/serve-web.ps1
```

После запуска игра будет доступна по адресу:

```text
http://localhost:8000/match3.html
```

## Архитектура

Игровая логика отделена от rendering-кода.

`match3_core` не зависит от raylib и содержит основную логику игры: работу игрового поля, поиск матчей, swaps, cascades, gravity, цели уровня и RNG.

`src/app` отвечает за пользовательский ввод, rendering, анимации и взаимодействие игровой логики с приложением.

Такое разделение позволяет тестировать основную игровую механику независимо от графического интерфейса.
